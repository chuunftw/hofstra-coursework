PART 3 - OBSERVERS_PROBLEM.CPP
What the program does:
- Stocks are observed subjects.
- Investors are observers.
- Investors hold portfolios of stocks.
- A stock notifies its attached investors when its price changes.
- Each investor's update() implements a different reaction.
- An investor may dump a stock and detach from it during an update.

Memory relationships:
- Investor portfolios contain shared_ptr<stock>.
- Stock observer maps contain weak_ptr<investor>.
- The investor destructor detaches it from its remaining stocks.
- The source requires C++17.

Required work:
[ ] Run the program several times as suggested.
[ ] Pinpoint the error and explain the exact causal lines.
[ ] Name the error type and trace the relevant calls.
[ ] Make a small, efficient correction.
[ ] Preserve the existing observer/investor behavior.
[ ] Give a short independent example of the same error.
[ ] Verify the corrected program, including a notification that triggers
    the panicky investor to detach.

Strict restrictions:
- Do not modify main.
- No cloning.
- Do not redesign the investment strategies.
- Address the actual memory error, not unrelated stock logic.
- The professor identifies the precise explanation as the MAIN task.

Useful functions to trace together:
    stock::price_change()
    stock::notify()
    panickyinvestor::update()
    investor::dump()
    stock::detach()

Concepts to learn:
- Observer pattern and virtual functions.
- shared_ptr versus weak_ptr.
- Container entries and iteration.
- What happens when a callback modifies the container being traversed.
- Smart pointers do not prevent every lifetime or iterator error.
