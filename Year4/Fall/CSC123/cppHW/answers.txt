Part 1 - Bubblesort

A[k+1] = temp; makes both rosters point to the same csc123 array.
When temp frees the array at the end of the swap, A[k+1].students
becomes a dangling pointer. Printing r.students[i] then causes a
use-after-free. If roster destructor runs later, a double free leak will occur. 

Changes to code: 
1. Replace "string* students" with "unique_ptr<string[]> students"
2. Replace "students = new string[count]" with "students = make_unique<string[]>(count)"
3. Remove the roster destructor. The unique_ptr frees the array.

The changes would not compile however, even after fixing the memory errors,
b/c of unique pointers not allowing copies to be made, you would need to use the swap function. 

Part 2 - Matrix

The clean() calls in main free the matrix arrays. When main ends,
the destructors try to free the same memory again (double free).
In C = A * B, C loses its old allocation and copies the temporary's
pointer. The temporary frees that array, so C.printm() reads freed
memory. multiply() can also read past a row if the dimensions don't match.

Changes to code:
1. Replace double* and double** storage with double1d and double2d
   unique_ptr types. Allocate the arrays with make_unique.
2. Pass arrays by reference when only borrowing them. Move ownership
   when replacing the matrix storage.
3. Remove clean(), the destructor, and the manual delete[] calls.
   The smart pointers free the arrays automatically (Rule of Zero).
4. In multiply(), return if y != m.nrows() before the loop runs.
   This prevents reading past the end of a row.


Part 3 - Observers

1. In notify() (line 171), update() can call dump(), which calls
   detach(). The erase on line 166 removes the entry the loop is
   visiting. This invalidates the iterator, and advancing it after
   update() returns is undefined behavior.

2. Replace the loop in notify() with:

   auto it = investors.begin();
   while (it != investors.end()) {
       auto observer = it->second.lock();
       ++it;
       if (observer)
           observer->update(*this);
   }

   The iterator advances before the investor can erase its own entry.

3. Small example of the same error:

   std::unordered_map<int, int> entries{{1, 10}, {2, 20}};
   auto it = entries.begin();
   entries.erase(it);
   ++it;  // Advances an invalid iterator
